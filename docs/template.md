# フェーズ教材テンプレート(執筆者向け)

各フェーズの `README.md` は、以下の構成で執筆します。学習者が「なぜこの作業をしているのか」を見失わないよう、必ず前フェーズの困りごとから書き始めてください。

## 執筆ルール

- 1文は短く、専門用語は初出時に一言で説明する
- 仕組みの解説は、可能な限り図(Mermaid)を使う
- ハンズオンは「コマンド」と「期待される結果」をセットで書く
- 確認課題は手順を書かず、ゴールだけを示す
- 振り返りの最後の問いは、次フェーズの「なぜ学ぶか」につなげる

## テンプレート

````markdown
# フェーズN:タイトル

> **ゴール**:このフェーズを終えたときにできるようになっていること(1〜2文)

## 1. なぜ学ぶか

- 前フェーズで起きた困りごと
- このフェーズの技術が、それをどう解決するか

## 2. 仕組みの解説

### 2-1. 概念A

説明と図

```mermaid
flowchart LR
    A[ブラウザ] --> B[サーバー]
```

## 3. ハンズオン

### Step 1. 〇〇する

```bash
コマンド
```

**期待される結果**:〇〇が表示される

## 4. 確認課題

- [ ] 課題1(ゴールのみ記載)
- [ ] 課題2

## 5. 振り返り

- 問い1(仕組みを自分の言葉で説明させる)
- 問い2(次フェーズの困りごとにつながる問い)

## このフェーズのファイル

`sample/` 配下のファイル構成と、各ファイルの役割

## よくあるエラー

| エラー | 原因 | 対処 |
| --- | --- | --- |
````
